# 农业分部数据 · 口径差异留档（awaken-agriculture-report-ingest 4.5）

> 2026-11-08。分部数据来自各公司 2024 年报正文，**同一字段在不同公司/不同交易所口径不一**。
> 本文件只记录差异与处置规则，**不做合并、不做换算**——差异在读数时就该看得见。

## 差异一：沪市年报不印「收入占比」，深市印

- **实测**：101 家里 **31 家**的分行业行全部没有 `revenue_pct`（全部为 60xxxx 沪市代码）。
  沪市版式是「收入 / 成本 / 毛利率 / 收入同比 / 成本同比」，深市版式是「收入 / 占比 / 上年收入 / 上年上年占比 / 同比」。
- **处置**：`revenue_pct` 一律取**报告自印值**，沪市为空即空——**不用「该行收入 ÷ 合计」自算占比填补**。
  理由：分部合计常含内部抵消，自算出的占比与报告口径不同，会把两个口径混在同一列。
- **影响**：`agri.segment.revenue_share` 覆盖 59 家（深市为主），不是全覆盖；读数时按公司是否披露区分。

## 差异二：分行业合并不等于总营收（内部抵消行）

- **实测**：牧原 2024 分行业含一行「养殖与屠宰、肉食之间销售抵消 **-24,435,772,335.76**」（负值），
  因此各业务收入相加 ≠ 营业收入。这是报告本身的表达，不是解析错误。
- **处置**：**保留负值抵消行原样**（不剔除、不折入相邻业务），并在读数时禁止用「各分部相加」当公司总营收。
  总营收一律取利润表口径（GTA/akshare 车道的 `financials.revenue`）。
- **另注**：抽取端会剔除「合计/小计/总计」聚合行（那不是分部），但**保留「减：…抵消」**这类带业务含义的负值行。

## 差异三：毛利率只在沪市版式出现

- **实测**：分行业行共 238 行，其中带 `gross_margin` 的 69 行，全部来自沪市版式（深市版式不印毛利率列）。
- **处置**：`gross_margin` 为空表示**该报告未按该版式披露**，不是「毛利率为零」。
  不派生（不用 `(收入-成本)/收入` 自算）——成本列在深市版式里也常常缺，自算会大面积造数。

## 差异四：分部命名各家用词不同（不做同义词归并）

- 同一业务各家用词不同：牧原叫「养殖业务 / 生猪」，天康叫「生猪养殖产业链行业」，金健叫「粮油食品加工业」。
- **处置**：分部名保留原文（`entities.name_zh` + `metadata_json.raw_name`），**不归并到统一码表**。
  跨公司对比时必须先有人工核过的对照表；在那之前只做「同一公司内部的分部结构」比较。

## 差异五：分部维度本身各公司不同

- 有的公司按「分行业」披露、有的只按「分产品」，有的两者都有且**内容还不同**（牧原两表业务名不同但数值相同）。
- **处置**：五个维度（`ind` / `prod` / `reg` / `sm` / `vol`）各自独立成实体，不互相替代、不互相校验。
  某维度缺失就是缺失，**不用另一维度顶替**。

## 可复核入口

- 抽取：`scripts/agri_segment_extract.py`（按需取全文 + 正则，带缓存，不写库）
- 登记：`scripts/register_agri_segments.py`（分部建成 `entity_type='segment'` 实体；两道自检：排除聚合行、数量级拒收整段）
- 锚：`scripts/verify_agri_segment_golden.py` + `docs/golden-agri-segments.json`（5 条锚取自年报原文，负例已验证会失败）

## 差异六：叙述式指标命中率低且易混入行业数据（4.2 实测）

- 7 条叙述式规则在 101 家里只命中 **21 家**（饲料销量 8 / 播种面积 4 / 制种面积 3 / 能繁存栏 3 / 均价 2 / 完全成本 1 / 批签发 1）。
  未命中的公司**不被推算**（不用分部表反推、不用行业均值顶替）。
- **必须拦的假命中**（实测两例）：
  - 大北农「**全国**生猪均价（外三元）在 14.63-20.63 元/公斤**区间波动**」→ 行业区间，非公司均价；
  - 金河生物「**据**中国兽医药品监察所…**调研**…**蓝耳苗**批签发 4.12 亿头份」→ 第三方行业数据且为特定疫苗。
  已用 `_NARRATIVE_EXCLUDE`（全国/行业/据…统计或调研/数据显示/区间波动）整条丢弃。
- 单位变体：牧原写 `13 元/kg`（英文 kg），只认「公斤/千克」的正则会漏抽 → 已补 `[kK][gG]`。
- 每条命中都落 `evidence`（原文片段），复核时以片段为准，不以数值自证。

## 差异八：登记驱动默认读试点产物，全量要显式 --extract（2026-11-08 返修）

- **症状**：库里有 18 个分部实体（跨 8 家公司）**只有收入占比/同比、没有收入金额**，
  例如海大集团「饲料行业」占比 83.57% 却查不到 957.75 亿元；牧原「养殖业务」
  （1362.29 亿元、98.75%）整条缺失。
- **根因**：`register_agri_segments.py` 的 `EXTRACT` 默认指向
  `docs/agri-segment-extract.json`（**4 家试点**），不是 `docs/agri-segment-extract-2024-all.json`
  （101 家）。重跑登记时若不加 `--extract`，只会回补试点那 4 家，其余 97 家的缺行永远补不上。
- **处置**：全量登记统一写 `--extract docs/agri-segment-extract-2024-all.json`；
  复验「有占比/同比但无收入」的实体数 = **0**，分部观测 2,165 条 / 742 个分部实体。
- **同时修掉的一处取整缺陷**：`_write_obs` 用 `f"{value:.6f}"` 会把 float 噪声印进 varchar
  （`136229329743.490005`、`-24435772335.759998`）。改为金额/百分比固定两位；
  清掉 4 条带尾值（留痕 `reports/agriculture-pilot/segment-precision-purge.json`）后重登记，
  牧原五条分行业、四条分产品金额与 golden 锚逐位一致。
- **看板侧**：图⑦ 由「财务细分面待回填」换成真实的**分部构成图**（头部 12 家 × 分行业口径，
  分部名保留原文、不跨公司归并，负的内部抵消行不参与堆叠）；取数账目按「每家公司一个合计」
  与堆叠合计逐点对齐，不再宣称「分部收入在册零条」。

## 差异九：两端默认产物路径已统一（2026-11-08 收口）

- 抽取端 `agri_segment_extract.py` 与登记端 `register_agri_segments.py` 原先默认都写/读
  `docs/agri-segment-extract.json`（**试点名**），而全量数据在 `docs/agri-segment-extract-2024-all.json`。
  后果是「以为重抽/重登记了全量、其实只动了试点 4 家」，正是差异八那 18 个实体缺收入的土壤。
- 现在两端默认**都指全量**；试点文件保留但写入 `superseded_by` 标记，不删除（历史可复核）。
- 登记端另加**覆盖度提示**：产物公司数少于白名单时会打印
  「产物只含 N 家（白名单 101 家）……」——小样本登记不再静默。
- dry-run 的计数措辞改为「观测计划」（原来写「观测写入」，会让人误以为已落库）。
