# SAMR 食品安全抽检源 — 字段级口径（task 2.4）

> change：`add-restaurant-vertical` · 任务 2.4 · 定稿 2026-11-07
> 源单元：`fd-industry-data/spiders/samr-food-inspection/`（`source_used = samr-food-inspection`）
> 抽取器：`fd-industry-data/scripts/restaurant_extractors/samr_food_inspection.py`
> 侦察原文：`data-source-scouting/restaurant/samr-food-inspection-scouting.md`

## 0. 一句话口径

这条源是**事件流**（一条公告 = 一个事件），不是上游发布的数值序列。本线只把它
聚合成**两周一个可复算的计数**，且只写真实出现过的月份。

## 1. `result_category` 三分类判定规则

| 值 | 判定 | 依据 |
|---|---|---|
| `unqualified` | 抽检**不合格**结果通报 | 标题含「抽检不合格」/「不合格情况」；正文首段出现「检出 N 批次样品不合格」 |
| `qualified` | 抽检**全部合格**类通报 | 标题含「全部合格」「合格情况通报」。**栏目内实测无实例**，是防御性档（不留空档） |
| `other` | 非抽检结果类 | 方法公告（「发布……快速检测方法」）、名录/废止、召回通告、建议答复、季度综合统计等 |

判定顺序：**标题规则优先**；标题无法判定时用正文首段兜底；两者结论矛盾时
**不硬判**——`result_category` 留 `None` 并跳过该条留痕（宁可缺一条，不错标一条）。

## 2. `restaurant_related` 命中规则

命中词表：`餐饮` / `食堂` / `餐馆`，以及前缀族「餐饮食品」「餐饮具」「餐饮服务」。

扫描面 = 标题 + 正文摘要 + **附件名**。附件名是餐饮覆盖面的唯一有效载体：
真实通报的餐饮条目几乎全部落在「附件N 餐饮食品监督抽检不合格产品信息.xlsx」
这类附件里，正文只写总批次。

两条边界必须记住：

1. **`restaurant_related` 是标注列，永远不作为过滤条件**——过滤由下游预警规则
   自己做（事件级预警只看 `unqualified AND restaurant_related`），源头不替下游丢数据。
2. **它表示「该通报的抽检覆盖面涉及至少一个餐饮类别」，不表示「该通报里所有不合格
   样品都来自餐饮」**。所以基于它算出的计数叫「餐饮相关通报条数」，不叫「餐饮不合格
   样品数」。
3. **会误命中**：实测 `2025-07-02 对十四届全国人大三次会议第7864号建议的答复`
   因正文谈及第三方检测机构的餐饮场景被标 `restaurant_related=true`，但它的
   `result_category=other`。这类误命中不会污染预警面（预警同时要求 `unqualified`），
   但会让「餐饮相关通报条数」这个宽口径偏大 → 引用时须带 category 限定。

## 3. 三种计数口径，别混

| 口径 | 含义 | 示例 | 本线是否使用 |
|---|---|---|---|
| 公告条数 | 一条通报算 1 | 「关于52批次食品抽检不合格情况的通报」= 1 | **是**（月度计数序列） |
| 不合格批次数 | 通报正文里点名的批次总数 | 同一通报 = 52 | 否（正文抽取，未做） |
| 抽检总批次 | 上游组织的抽检样本总量 | 同一通报 = 1940（检出 52 不合格） | 否，**且不作分母** |

副本：「抽检不合格率 = 52 / 1940」看起来诱人，但分母的统计范围（品类覆盖、
批次抽样方式）在整个栏目里不一致，跨月不可比 → 本仓库不产出该比率。要率，先立
口径专案。

## 4. 月桶与缺口

月桶 = `notice_date[:7]`（列表页 `contenttime` 锚定日期；缺失时回退正文 meta
`PubDate` 的日期部分；都没有 → 该条不归月，计数跳过并留痕）。

**缺失月不补 0**：某月零公告有两种可能——真无通报，或该月未被抓取覆盖。库里无法
区分，补 0 就是把「不知道」写成「零」。因此序列不保证日历连续；`notes` 显式给出
缺口月数（首跑实测：不合格通报序列 43 个真实月份 / 15 个月历缺口）。

## 6. 落库形态：**不写观测**（读时统计）

| 消费面 | 形态 | 实现 |
|---|---|---|
| 事件行（预警） | 读 `crawl_items` 原始 payload，`unqualified AND restaurant_related` 即预警候选 | 波4 事件级预警 |
| 月度统计（板面） | 读时现算，带 `as_of` 与口径注记，**不落 `semantic_observations`** | `scripts/restaurant_extractors/_samr_readtime.py::counts_by_month()` |

月度计数曾按「不合格通报条数 / 餐饮相关通报条数」两条概念试写入（2026-11-07，
69 行 + 2 概念 + 2 registry 条目），**当日回滚**：上游从未发布「月度通告条数」这个
指标，它属抽取端派生的聚合，与 `industry-observation-supply`「观测=上游发布的点、
抽取不派生」的纪律冲突（`add-restaurant-vertical` tasks.md 2.3 的契约边界裁定）。
回滚后库内该源观测数为 0，计数改由板面/预警读时现算。

首跑读时统计实测（2026-11-07，100 条公告）：

| 指标 | 值 |
|---|---|
| `unqualified` 通报 | 65 条（其中 `restaurant_related=true` 35 条） |
| `unqualified` 真实月份窗口 | 2022-01 → 2026-10，43 个真实月份（日历缺口 15） |
| `restaurant_related` 真实月份窗口 | 2022-09 → 2026-10，26 个真实月份（日历缺口 24） |

两条统计都 `entity_type=country` / `entity_id=1（CN）`；`restaurant_related` 是
`unqualified` 的**子集**，不是并列的第二口径。


## 7. 挂账

- `qualified` 档零实例 → 判定规则未经真实样本验证，一旦出现须人工复核后回填本文档。
- 不合格**批次数**（正文抽取）与附件明细未解析 → 细分面（哪些餐饮品类、哪些
  不合格项目）不可得，板面不得暗示可得。
- 「抽检公布查询页」（`spcjsac.gsxt.gov.cn`）未接入 → 历史逐条查询能力缺失，当前
  只有栏目列表页口径。
