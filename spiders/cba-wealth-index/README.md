## 批次目录陷阱（本单元的核心坑）

附件 href 是**站根相对路径**，形如：

```
/Uploads/ueditor/file/20261012/6acc86244d7a6.pdf
/Uploads/ueditor/file/20261019/6ad589a214386.pdf
```

`/file/<YYYYMMDD>/` 是**这一批附件的上传日期，不是报告期**。实测：

| 年度页 | 批次目录 → 实际期号 |
|---|---|
| 2026 | `20261012/` → 1 月、2 月、3 月、4 月、5 月、6 月、7 月、8 月（8 期同一目录）；`20261019/` → 9 月 |
| 2025 | `20250519/` → 1–4 月；`20250724/` → 5–6 月；`20250911/` → 7 月；`20250917/` → 8 月；`20251110/` → 9 月 |
| 2024 | `20240919/` → 2–8 月；`20241127/` → 1 月、9 月、10 月；`20241218/` → 11 月；`20250123/` → 12 月 |

由此产生三种"抓错年份/期号"的现实路径，本单元逐一防住：

1. **用目录日期当报告期**：同目录装 8 期，任何"目录月份=期号"的假设都会把
   2026-01…08 全部错标成 2026-10。
2. **用文件名当报告期**：文件名是 32 位 hex（`6acc86244d7a6.pdf`），期号只在
   **锚文本**里（`中国银行业理财市场指数报告（2026年9月）.pdf`，且 2024 页部分
   文案是半角收尾 `（2024年1月)`）。本单元只从锚文本正则
   `[（(]\s*(20\d{2})\s*年\s*(\d{1,2})\s*月\s*[）)]` 取期号。
3. **列表顺序 ≠ 时间顺序、同期重复挂链**：2024 页首条是 2024-12（2025-01-23
   批次），下面才是 1 月；2022-2023 页把 `2023年1月` 挂了两次
   （`20230221/63f436c9d9a77.docx` 与 `20240130/65b854032bebc.docx`，两次文件
   sha256 相同 `14e32919…`）。本单元按 `period` 去重，同期多份取**批次日期最新**
   的一份，其余留痕丢弃。

另有一道交叉校验：每份文档标题里的 `（YYYY 年 M 月）` 会与锚文本期号比对，
不一致时打 `期号交叉校验不一致` 留痕（仍按锚文本入库）——防的是上游把旧文件
重新挂到新批次下。

## 两条解析通道

### PDF（2024-01 起）：`fd_industry_data.pdftext.extract_text(payload, layout=True)`

poppler `pdftotext -layout` 实测有完整文本层（**不是扫描件，无需 OCR**），
2026-09 期首段实抽：

```
截至 2026 年 9 月 30 日，全国现金管理类产品的平均近 7 日年化收益率为
1.10%，较 8 月 31 日持平，较基期下降 171BP。
...
9 月，全国银行理财市场固收类产品收益指数为 111.93 点，环比上升 0.13
点，涨幅 0.11%，延续上涨态势，涨幅较上月有所下降。指数较基期上升 11.93
点，增长 11.93%。
```

`pdftotext` 会在数字与汉字之间插空格（`2026 年 9 月`、`109.31 点`、换行把
`1.10%` 甩到下一行），所以正文匹配统一在**去空白串**（`re.sub(r"\s+", "")`）
上做，正则要点：

| 指标 | 正则（去空白后） |
|---|---|
| 现金管理指数 | `现金管理类产品收益指数为([0-9.]+)(?:点)?` |
| 现金管理 7 日年化 | `(?:平均近7日|平均七日|月均七日)年化收益率为+([0-9.]+)%`（`为+` 兼容 2024 年原文的「为为」） |
| 固收总指数 | `全国银行理财市场固收类产品收益指数为([0-9.]+)(?:点)?`（前缀「全国银行理财市场」把短/中/长期子指数排除） |
| 短/中/长期 | `(短期|中期|长期)固收类产品收益指数为([0-9.]+)(?:点)?`，截到 `；`/`。`/`图表` |
| 环比 | `(?:较上月)?环比(上升|下降|…)([0-9.]+)(点|%)?`；单位为 `%` 时不落 `mom_change_point` |
| 月度涨幅 | `(?:环比)?(涨幅|降幅)([0-9.]+)%`；无「幅」措辞时回退 `(增长|降低|下降|上升)([0-9.]+)%` |
| 较基期 | `较基期(?:月|月均值|周|周均值)?(上升|下降)([0-9.]+)点` + 同句 `(增长|下降|降低)…%` |
| 区间收益 | 先 `…{期限}固收类产品过去三个月投资收益为([0-9.]+)%`，再同一句后 120 字内找 `过去六个月投资收益(?:为|达)([0-9.]+)%`——**六个月常省略主语**，只按主语搜会漏 |

方向词统一带符号：上升/增长/上涨为正，下降/下滑/降低/回落为负，持平为 0。

### docx（2022-02 … 2023-12）：`zipfile` + `xml.etree`

`word/document.xml` 的 `w:body` 下按文档序 `iter(w:p)`，拼接每个段落的 `w:t`
文本。**不能用正则 `<w:t[^>]*>`**：它会把 `<w:tabs>` 当成文本节点，实测会把
`w:tab`/`w:spacing` 等标记碎片拼进正文。表格里的段落同样被 `iter(w:p)` 覆盖，
但本单元的数值全部取自正文（表格只用于人读核对），因此不需要 `w:tbl` 结构化。

旧模板（2022-02…2023-12）的措辞与新模板完全不同：

```
2023年12月31日，全国精选60款现金管理产品当周七日年化收益率平均值为2.28%，
较12月24日当周均值环比上升7BP，较基期周均值下降99BP。
12月，全国精选60款非现金管理类中低风险六个月投资周期产品综合价格指数为
110.49点，环比上升0.34点，环比涨幅0.30%，指数较基期月上升10.49点，增长10.49%。
```

对应 `methodology=selected60_price_index`、`series=selected60_cash /
selected60_price_6m / selected60_price_1y`。

**实测状态：docx 端点活着，未被改版/下线。** 2026-11-08 用本单元真跑
`period=2023-12, months=2`：两期均 `docx`、`selected60_price_index`、**每期 13 行**、
耗时 3.6s（年度页过滤生效，只请求了 2022-2023 页）。因此代码保留完整 `PK`
分支，不是"为将来预留"。

## 口径断层（2024-01 切换，必须分列）

- **2024-01 起**（新）：现金管理类 / 固收类产品**收益指数**，基期
  2021-12-31=100。
- **2022-02…2023-12**（旧）：普益「精选 60」模板，现金管理是**周度**七日年化，
  另两条是六个月 / 1 年投资周期**综合价格指数**；基期周为 2021-04-04。

两者样本与基期都不同（旧 104.91 与新 111.93 不可比），所以输出用
`methodology` 列强制区分，`series` 也不复用（`selected60_*` vs `fixed_income*`）。
把两段拼成一条序列是错误用法，README 与 manifest 列描述均写明。

## 上游数据异常（如实记录，不修补）

- **2024-01 长期固收**：原文「环比上升 0.27%」，单位为百分比而短/中/总都是
  `点`；本单元不把它伪造成点数，该期 `mom_change_point` 缺测，仅保留同句
  「环比涨幅 0.26%」→ `mom_change_pct=0.26`。
- **2024-06 现金管理**：原文「指数为 67.02，较上月环比上升 0.86 点，涨幅
  1.30%」，但 67.02−66.89=0.13，上游自相矛盾；按原文值落库（index 67.02 /
  mom 0.86 / 涨幅 1.30%）。
- **2024-01 / 2024-02**：该两期正文没有「区间投资收益」段，故只有 25 行/期
  （缺 `return_3m_pct` / `return_6m_pct`），不是解析失败。

## 失败策略

- 年度页失败 → 留痕后跳过其余年度页继续（单页故障不拖垮整次）；全空 →
  `RuntimeError`（失败即红，绝不静默回空表）。
- 单期附件下载/解析失败（网络、非 PDF/docx 魔数、zip 缺 `document.xml`、
  `pdftotext` 非零退出/无二进制）→ 留痕跳过该期；**所有期都解析不出指数值** →
  `RuntimeError`。
- PDF 无文本层（`pdftotext` 返回空串）会被当作"未解析出指数值"留痕，不做 OCR。
- 未知附件魔数 → 抛 `ValueError` 并按上一条留痕。
- 请求间隔：`_throttle()` 保证任意两次 HTTP 请求间隔 ≥1s；瞬时网络错误重试一次。
- `limit` / `months` / `period` 三个声明参数都真实生效：`limit` 截断长表、
  `months` 按期回溯、`period` 钉死起点期并按年份过滤年度页（避免为取 2023-12
  去拉 2026 页）。

### 与 2026-10-13 NFRA 规则的关系

该裁决排除的是"正文只有扫描图片、无文本层、需 OCR"的 PDF。本源的 PDF 实测
`pdftotext -layout` 可直接抽出指数表正文（见上引原文），**属正常文本层 PDF，
不在排除范围，也不需要 OCR**。真正不可得的只是"2026-10 及以后尚未发布的期"，
那是发布节奏，不是抓取障碍。

## 为什么 golden 钉 `period=2026-09`

理财指数每月变动；若 golden 取"站点最新期"，下月一发布，`period` 与
`value=111.93` 两个锚同时失效——那是 golden 写法错，不是缺陷。因此入口增加
第三个可选参数 `period`（`YYYY-MM`，空=最新期）：

- golden 用 `period=2026-09` 钉死历史月，锚值（固收类 111.93 点、现金管理
  39.00 点、短/中/长期 111.02/112.38/113.47）长期成立；
- 调度口径不变（`period` 空 → 站点最新期）；
- 顺带满足历史回补：2022-02 起任意月份都能取，不改代码。

这是相对任务原文的**增量**（多一个可选参数），不是收窄：默认行为与 spec 一致。
golden 另用 `file_format=pdf`、`methodology=fixed_income_return_index` 两个结构锚，
以及 `return_6m_pct=0.86`，同时证明 PDF 分支与"区间收益省略主语"的解析路径。
docx 分支的活力由上面的 `period=2023-12` 实跑留痕，不额外增加 golden（避免健康
巡检多打两次网络）。
