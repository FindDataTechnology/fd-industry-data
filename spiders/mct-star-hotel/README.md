## 坑位与容错（侦察 + 实跑逐条落实）

1. **附件名不符实**：2024Q1 附件 1/2 声称「经营情况统计表 / 按星级分」，内页其实是
   「全国各地星级饭店统计情况完成表」（`星级饭店总数/完成数/退回重填/停业饭店数/合格率`，
   合计 7947/6295/13/861/90.21），且两份逐单元格完全相同。
   → **不按附件名、不按附件序判定表类型**，一律读内页标题（`_classify`）；命中
   `audit-completion` 整份跳过并留痕。绝不把审核完成率当经营指标入库。
2. **列名映射按标题不按列序**（任务 2.4）：表头可能跨两行、单元格内带换行
   （`一星饭店\n数量`），统一压空白后查表；**任何一列映射不中即硬失败**
   （`UnmappedColumn` → 整次运行 `RuntimeError`），上游改表必须炸，不能静默少列。
3. **星级表是合并表头**：档位前缀只出现在每组首格，第 3 列原文是 `平均房价\n(元/间夜)`
   不带前缀 → 必须前向继承 `current_star`，否则整组落到上一档或被丢。
4. **50 城表的「全国」行是 50 城小计**（2024Q3：2209 家 vs 全国 6129 家）→ `area_kind`
   分开标，抽取器据此分落，绝不混算成全国。
5. **空值是全角「－」**（U+FF0D），不是 `-`、不是空、更不是 0。
6. **同比列与量值列同表**：`平均房价同比（%）` 与 `平均房价(元/间夜)` 是两列，
   slug 必须区分（`adr` vs `adr_yoy`），否则同比冒充量值。
7. **年度 `.xls` 单位不同**（`千元/间·年` vs 季度 `元/间·季`）→ 本单元**只取季度 xlsx**，
   年度附件整份跳过并留痕，不做单位换算。
8. **相对链接必须 `urljoin` 且 base 不补尾斜杠**：栏目页里的详情链接是
   `../../tjxx/202412/t20241226_957396.html`；`base + href` 会造出非法主机，
   补尾斜杠会少退一级 → 全部 404。
9. **失败即红**：单页/单附件失败只留痕；出现 `UnmappedColumn` 或全部期次失败 → `RuntimeError`。
   无 `schedule`，失败不重试放大。

## 历史深度

栏目共 40 页静态分页，星级饭店季报最早可回溯到 2022Q4（`pages=3` 即可覆盖全部 8 期）。
`pages` 上限 12；再往前翻只需调大 `pages`（同构解析）。注意 2022Q4/2023Q1 只有「完成表」，
翻了也没有经营数据。

## golden 断言口径（跨期稳定）

`golden/001-mct-star-hotel.json`（`periods=2024Q3`、`pages=1`、`limit=5000`）锚的是
**已发布即冻结**的 2024Q3 历史值（`rows_contains` 是逐条 any-row 语义，值锚独立成立）：
全国 `count=6129.0` / `revenue=390.01` / `adr=375.1` / `occupancy=52.96` / `revpar=198.66`，
50 城小计 `count=2209.0`，四张表类型各一条，`min_rows=1800`。
**绝不锚 `scraped_at` / `doc_url` / `xlsx_url` / `report_title`**（列在 `whitelist_fields`）。

> 该系列已断更，锚值不会再漂移；如果哪天 MCT 复更，先看 `LAST_TRACES` 再决定是否扩锚。
