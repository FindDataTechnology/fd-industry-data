新源接入档案（批次六·银行业，change `add-banking-industry-sources` 任务 4.1）。

## 端点（从栏目页 JS 实读，2026-11-08）

页面 `https://www.shclearing.com.cn/cpyyw/ywsj/tjyb/`（统计月报），
`images/home.js` 定义 `shclearing.app_root = "/shchapp/web/"`，
`images/cpyyw_tjyb.js` 给出三个调用：

```js
// 1) 最新已发布月（返回 "YYYY-MM-DD"）
POST /shchapp/web/sdocClient/getMaxDate

// 2) 某年月的月报目录（channelId 固定为「统计月报」节点）
POST /shchapp/web/sdocClient/monthListPage
data: { title: "", operTime: "YYYY-MM",
        channelId: "ff80808140a43ba80140a45b17320007",
        limit: 10, start: 0 }

// 3) 附件下载（attachmentId 来自目录项的 downloadPdfUrl/downloadExcelUrl）
GET  /shchapp/web/sattaClient/download/<attachmentId>
```

实测（2026-11-08，本机直连）：

| 请求 | 结果 |
|---|---|
| `getMaxDate`（空 body） | `"2026-09-30"`（最新已发布月 = 2026-09） |
| `monthListPage operTime=2026-09 channelId=ff80808140a43ba80140a45b17320007 limit=10 start=0` | `flag="0"`，`data` **7 条** |
| 目录内容 | 汇总 xlsx（`上海清算所债券业务月度统计报表（2026年9月）.xlsx`）+ 表一…表五 PDF + 报表项目说明 PDF |
| `sattaClient/download/<表四 id>` | 43,214 B，`%PDF-1.7` |
| `sattaClient/download/<表五 id>` | 48,350 B，`%PDF-1.7` |
| `sattaClient/download/<汇总 xlsx id>` | 25,251 B，`PK\x03\x04`（OOXML） |

`channelId` 是 app 树里的「统计月报」节点。侦察簿特别提示：**不要与 TRS web 树的
频道 ID 混用**（`ff80…0007` 只属统计月报；TRS 是 ch166/ch144 另一套 ID 体系）。

## 三重门怎么过

侦察簿记录的「JSESSIONID + Referer + 魔数」三道门，本次逐条复验：

1. **会话门**：先 `GET https://www.shclearing.com.cn/cpyyw/ywsj/tjyb/` 建会话
   （cookie 罐接手任何 `JSESSIONID`）。实测不先 GET 直接下载 → 302
   `http://www.shclearing.com.cn/shchapp/pages/common/error.jsp`（`Content-Length: 0`）。
2. **Referer 门**：所有 `sdocClient` / `sattaClient` 请求必须带
   `Referer: https://www.shclearing.com.cn/cpyyw/ywsj/tjyb/`。实测「有 Referer、
   无 cookie」当前也能 200（上游可能放宽了会话校验），但本单元仍先建会话再请求，
   以兼容收紧后的行为；「有 cookie、无 Referer」侦察期实测返回空 success /
   页面不存在。
3. **魔数门**：`Content-Type` 一律撒谎为 `application/x-msdownload;charset=UTF-8`，
   扩展名与响应头都不可信。本单元对 PDF 走 `pdftext.is_pdf(payload)`（`%PDF-`），
   对 xlsx 走 `tabular.detect(payload) is Format.XLSX`（`PK\x03\x04`）；
   任一不符即 `ValueError`，绝不把 `error.jsp` 的 HTML 当附件入库。

## 失败的尝试与证据（PDF 直接解析）

先按任务设想的「PDF → 文本 → 表格」路径实做：

- `pdftotext -layout` 对表四可用：22 行文本，`2.2 商业银行金融债 99,189.83`
  与 xlsx 完全一致。
- 表五串列严重：表头跨 **3 行**（券种大类行、券种子类行、空行），
  `资产支持\n证券`、`标准化\n票据` 在文本里被折断；列间空档宽度不等
  （同一行 `129.20` 前 14 空格、`0.00` 前 7 空格），按固定列位或
  「2+ 空格一次切分」都无法把 10 个券种列稳定回推成列名。PDF 抽出的
  合计行 `14,709.99 18,625.81 … 0.00` 只有 10 个数，而表头行有 11 个文本块
  （含分组标签），按空格对齐会错位一列——这会**静默把「金融债券」列的值
  记到「同业存单」列**，比丢行更危险。

因此本单元的解析口径是：

1. 同一期目录里还有**同一发布批次的汇总 xlsx**（`上海清算所债券业务月度统计报表
   （YYYY年M月）.xlsx`，含 `表四`/`表五` 工作表），是原生行列结构，走共享层
   `fd_industry_data.tabular.read_grid(sheet=...)`——满足「表格解析必须走
   tabular」；
2. 两份 PDF **照常下载并魔数校验**，再用 `pdftext.extract_text(payload, layout=True)`
   抽文本，对两个锚点值做抽查：`表四 2.2 商业银行金融债/本月末 = 99,189.83`、
   `表五 2.存款类金融机构/金融债券 = 51,463.82`（xlsx 值 `51463.824572`
   按两位小数格式化为 `51,463.82`），确认 PDF 与 xlsx 同源同值；
3. 若某期目录只有 PDF、没有 xlsx，才回退到「按 2+ 空格切列」的**行级**解析
   （`_pdf_gap_rows`，仍输出 row_label/metric/value 长表），表五列序取上游固定的
   `METRICS_05`，值个数不符即留痕跳过，不猜列。该路径本次未触发（每期都带 xlsx）。

## 与中债登通道（`chinabond-monthly`）的对账

同为 2026-09、同为「登记托管口径」，但**两个所在托管人维度互斥**：上清所只统计
在自己处登记托管的债券，中债登只统计在自己处托管的债券。所以**不可期望相等，
也不可把两所的「商业银行」数值直接相减/相加当成同一口径**；可做的是规模量级与
构成比例对账：

| 指标（2026-09，亿元） | 上清所 | 中债登 | 合计 | 上清所占两所合计 |
|---|---|---|---|---|
| 期末托管面额（全市场） | 546,141.99715401（表四 合计） | 1,365,657.5632941716（统计月报 04/05 合计） | 1,911,799.56 | 28.6% |
| 商业银行相关持有/托管 | 表五 `2.存款类金融机构` 10 券种合计 ≈ **162,531.80**（由 4,752.192 + 3,714.02279 + 1,825.01 + 35,281.429098 + 2,163.992 + 51,463.824572 + 61,308.15549 + 1,976.8256 + 46.351 + 0 得） | 表 05 `1.商业银行` 托管面额 = **886,790.8119340657** | ≈ 1,049,322.61 | 15.5% |

结论：

- **不可比（等值）**：两所是不同托管人，分母不同；上清所的「存款类金融机构」还
  包含信用社、村镇银行等，中债登的「商业银行」分级也不同，逐值相等既不可能也不
  应该期待。
- **可比（量级/构成）**：两所合计 1.91 万亿元级（191 万亿）与我国债券市场托管
  总规模同量级；上清所占 28.6% 的全市场托管、占商业银行持债 15.5%，均落在
  「上清所是较小一极」的合理区间。若未来出现上清所单所托管量超过两所合计、
  或商业银行占比数量级跳变，才作为「疑似源改版/串列」告警。
- 本次对账**不做数值相等断言**，只把上述数字登记为规模校验基线；golden 锚的是
  上清所自身 2026-09 的已知值，避免用另一所的数值当期望值。

## 失败策略

- 目录 `data` 为空 = 该月未发布：继续往回探测（上限 `months+4` 次）；网络/非 JSON/
  `flag != "0"` 留痕后同样继续；整个探测窗无表四表五 → `RuntimeError`。
- 单表下载失败 → 留痕；xlsx 失败 → 回退 PDF 文本行级解析；单个 PDF 失败 →
  其余表照常出数。
- 缺表四/表五（目录不完整）→ 该期留痕跳过，不猜表名。
- 附件魔数不符（PDF 非 `%PDF-`、xlsx 非 `PK`）→ `ValueError` 并留痕，绝不入库。
- 上游空单元格 / `-` / `---` → 该（行, 指标）不出行（不写 0，避免把「未披露」
  伪造成「零」）；上游真实 `0.00` 照常出行。
- 网络礼节：每次请求之间 `time.sleep(1.2)`；单期 5 个请求，`months>1` 时按期线性
  增加，不做并发。

## 为什么 golden 钉 `period`（参数存在的理由）

月报数值每月变化，若 golden 用「最新期」，新一期一发布锚值立刻失效——那是写法错，
不是缺陷信号。因此入口除 `limit`/`months` 外增加第三个参数 `period`
（`YYYY-MM` 或 `YYYYMM`）：

- golden 用 `period="2026-09"` 钉死历史月，锚
  `表四 2.2 商业银行金融债/本月末 = 99189.83`、
  `表五 2.存款类金融机构/金融债券 = 51463.824572` 长期成立；
- 调度口径不变：`period` 空 → `getMaxDate` 给的最新已发布月；
- 同一参数顺带满足「2014-12 起历史回补」——任何历史月份都能取，不改代码。

这是相对任务原文的**增量**（多一个可选参数），不是收窄：默认行为与 spec 一致；
三个声明参数（`limit`/`months`/`period`）在入口签名中均显式存在并真实生效
（`limit` 截断、`months` 控制回溯期数、`period` 定起点月）。
