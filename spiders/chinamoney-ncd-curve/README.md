## 端点（从站点前端 fragment 实读）

fragment `/r/cms/chinese/chinamoney/html/bond/cls-yld-curv-cn.html` 的 JS：

```js
url: BK_URL + 'cm-u-bk-currency/ClsYldCurvHis?lang=CN&reference=' + referenceList
     + '&bondType=' + bondType + '&startDate=' + d + '&endDate=' + d
     + '&termId=0.5&pageNum=1&pageSize=50'
type: "POST"
```

曲线码表来自同模块 `ClsYldCurvCurvGO`（实测 75 条），同业存单一族：

| bondType | 曲线名 |
|---|---|
| **CYCC41B** | **同业存单(AAA)** ← 本单元 |
| CYCC41J | 同业存单(AAA-) |
| CYCC41C | 同业存单(AA+) |
| CYCC41D | 同业存单(AA) |
| CYCC41K/L/M/N | 同业存单(AA-)/(A+)/(A)/(A-) |

`reference`：1=到期收盘 / 2=即期 / 3=远期。NCD 取 **1（到期）**，行键用 `maturityYieldStr`。

## 两个硬坑

1. **只能单日查**：把 `startDate`/`endDate` 给成区间（2026-08-01..2026-11-07）
   实测 **0 条**；给单日（2026-10-20）返回 **17 个期限点**。故本单元按**交易日逐日**
   走（跳过周末），不做区间查。
2. **行在顶层 `records`**（与 Shibor/LPR 同构），`data` 只放元信息。

期限集合（实测 17 个，`yearTermStr` 年化）：`0.019 0.038 0.058 0.083 0.125 0.167
0.208 0.25 0.333 0.417 0.5 0.583 0.667 0.75 0.833 0.917 1.0`（≈1W…1Y）。

## 即接即累积（design D3 落地）

线上**只滚动约 2 个月**，历史不可回补。因此：

- 本单元每次运行只走 `days` 个自然日的回溯窗（默认 45 ≈ 30 个交易日），
  连续 3 个交易日为空即判「已越过滚动起点」提前收工；
- **序列自点亮日起累积**，不做历史回补（design 明确不回补）；
- 中断即缺段，由既有 `gap_in_series` 断档检测兜底；
- README 与 manifest 均写明该 caveat（spec 要求 caveat 随序列声明）。

## 为什么 golden 不锚数值

tasks.md 3.3 写「golden 锚=点亮日最新值」。落地时改为**结构锚**并在此留痕原因：
该序列每日全量变动，锚单一数值的 golden 在点亮后**第一个交易日就会 fail**
（`health.guard.classify_failure` 会把它归到 `sample-update-pending-human`，
变成每日噪音而不是缺陷信号）。代替方案：

- 锚 `tenor_years` 全集关键点（0.019 / 0.083 / 1.0）+ `tenor_days=365`，
  上游若改期限结构立刻红；
- 锚 `curve/curve_name/reference/unit`，上游若改曲线码或口径立刻红；
- `min_rows=80` 保证「有数且够宽」；
- 点亮日数值本身登记在本 README（上文快照），供人工核对首次落库值。

## 失败策略

单日失败 → 留痕并继续（假日/临时故障不会中断整条回溯）；连续 3 空 → 提前收工；
整窗无任何点 → `RuntimeError`；缺测（`---`）不出行；`limit` 与 `days` 均真实生效。
