# lh-ratings —— 联合资信 银行跟踪评级（定期跟踪评级栏目）

新源接入档案（批次六·银行业，change `add-banking-industry-sources` 任务 6.3）。

## 端点与分页（全部实测，2026-11-08）

栏目入口：`https://www.lhratings.com/lists/111.html`
（导航「评级结果 → 定期跟踪评级」；页面静态渲染，无 JS 接口）。

**分页参数是 `?p=`，不是 `?page=`**——页脚与跳转脚本都写 `?p=`：

```html
<a href="/lists/111.html?p=2" val-page="2"> 2 </a> …
<input type="text" name="page_num" value="1" class="page_num" end_page="2927">
```

```js
location.href = "/lists/111.html?p=" + page;
```

服务端标题过滤参数是 **`title`**：

| 请求 | `end_page` | 首页条数 | 条目总数 |
|---|---|---|---|
| `/lists/111.html?p=1`（未过滤） | **2927** | 12 | ≈ 35000（12/页） |
| `/lists/111.html?title=银行&p=1` | **7** | 12 | **78**（前 6 页各 12 + 末页 6） |

→ `title=银行` **服务端生效**：页数 2927 → 7。请求 `p=8/9/9999` 均返回
**HTTP 200 且 0 条**（不是 404），所以分页循环以「空页」为终止条件，不硬编码页数。

过滤口径是**标题子串匹配**，会命中「银行**间**票据」这类非银行发行人
（实测 78 条中有 1 条：烟台市财金发展投资集团有限公司 2025 年公开发行银行间
票据跟踪评级报告）。本单元**不做本地二次收窄**：收窄会掩盖上游过滤口径，
且 `keyword` 是显式参数，调用方可用更精确的词。这是已知的口径特征，不是缺陷。

## 条目结构（7 页 78/78 条完全一致）

```html
<li>
  <a href="https://www.lhratings.com/reports/<id>.pdf" target="_blank">
    <div class="dqgzbox">
      <div class="dqleft">
        <h2>2022年重庆银行股份有限公司公开发行A股可转换公司债券</h2>   <!-- 债项名 -->
        <h2>重庆银行股份有限公司…2026年跟踪评级报告</h2>              <!-- 报告标题 -->
        <p>2026-05-23</p>                                            <!-- 发布日期 -->
      </div>
      <div class="dqright">
        <p>主体级别：AAA</p>
        <p>展望：稳定</p>
        <p>债项级别：AAA</p>
      </div>
    </div>
  </a>
</li>
```

- 是 **div/li 列表，不是表格**，故用字符串 + 正则解析，不涉及 `tabular`
  （gate 的 `inline-tabular-parser` 只针对工作簿解析）。
- 详情链接**直接就是 PDF**：`https://www.lhratings.com/reports/<债券代码>-<报告代码>-GZ<年份>.pdf`
  （早期条目也有 `/uploads/file/YYYYMMDD/<hash>.pdf` 形态）。实测 78/78 条
  均为 `.pdf`，没有 HTML 详情页中转。
- 上游 `target="_blank""` 有一个多余双引号（笔误），解析时用 `[^>]*` 吞掉。
- 发行人从第 2 个 `h2` 的公司名后缀（股份有限公司/有限责任公司/有限公司）抽取；
  公告类标题以「联合资信评估股份有限公司关于…」「联合资信关于上调…」开头，
  先剥掉评级机构前缀与「关于/上调/将…」动词再取公司名（实测
  「联合资信关于上调广西北部湾银行…」→ `广西北部湾银行股份有限公司`）。

## 增量口径：只巡检前 N 页，不回扫 2927 页

栏目共 **2927 页**（约 3.5 万条历史），本单元默认 `max_pages=5`
（最近 60 条列表项），原因：

1. **成本/礼貌**：2927 次请求 × ≥1s 间隔 ≈ 50 分钟，对上游是明显的负担；
2. **无必要**：跟踪评级按发行人年度/事件驱动发布，前 5 页已覆盖最近数月到
   数年新增；上游列表按日期倒序，最新条目永远在第 1 页；
3. **历史回补可控**：需要旧条目时显式传大 `max_pages`，而不是默认全扫。

因此本单元的增量口径 = **只巡检前 `max_pages` 页的最新条目**，不做全量对账。
这也是 `data_period: irregular` 的理由：数据本身没有固定自然周期（发行人年度
跟踪 + 不定期公告），每周调度只是滚动巡检，不是「每周应有一条新数据」。

## 去重

上游列表存在**完全相同的 PDF URL 被列两次**（7 页 78 条中 8 个重复 URL，
去重后 70 条；前 5 页 60 条中 5 个重复）。本单元按 `url` 去重并留痕
（同一份披露只落一行）；**不**按 (发行人, 年份) 去重——同一发行人同一年份的
不同债券确实是不同 PDF，合并会丢数据。

## 失败策略

- 单页请求失败（`URLError`/超时）→ 留痕跳过该页，其余页照常出数；
- 某页 0 条 → 视为越界页正常终止（实测 p=8/9/9999 均 HTTP 200 + 0 条）；
- 一页都没抓成，或所有页都没有可解析条目 → `RuntimeError`（不静默返回 `[]`，
  避免把「版式漂移/过滤词失效」伪装成「今天没数据」）；
- 单条目 `h2` 不足 2 个（版式漂移）→ 留痕跳过该条，不猜字段；
- `limit` / `keyword` / `max_pages` 均真实生效：`limit<=0` 或 `max_pages<=0`
  返回 `[]`，`keyword` 空串 = 不过滤（全量 2927 页），`max_pages` 控制巡检深度。

## 为什么 golden 这样锚

`expect.rows_contains`（只支持 `{field, equals}`）锚三组：

1. ~~常量~~ 信封字段：`source=lh-ratings`、`doc_type=定期跟踪评级`、
   `keyword=银行`——证明跑的是本单元、走的是过滤通道；
2. **一条较早且稳定的银行条目**：`issuer=中国建设银行股份有限公司` +
   `report_year=2019` + `rating_date=2019-07-19` + 精确 PDF URL
   `…/A0009-CJZQ0077-GZ2019.pdf`——2019 年的披露不会滚动消失，且
   `max_pages=8` 给它留了 4 页（≈48 条新增）的滚动余量；
3. **一条公告类条目**：`issuer=晋中银行股份有限公司` + `report_kind=公告` +
   `report_year=2021`——锁住「联合资信关于…公告」的发行人称谓归一化，
   防止只测普通跟踪报告而漏掉公告分支；
4. 一条最新条目：`rating_date=2026-05-23` + 精确 URL——证明列表确实按日期
   倒序、最新一条可读。

列表按日期倒序会滚动，故**不锚页内序号**，只锚内容等值字段；`max_pages=8`
（默认 5 之外显式加深）是为了让第 3/4 组锚在未来新增条目把老条目推到更后页时
仍有覆盖。`scraped_at` 进 `whitelist_fields`。
